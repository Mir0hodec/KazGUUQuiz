# Полная симуляция турнира

Боты-команды подключаются к настоящему серверу по WebSocket и играют весь турнир **в реальном времени**, так, как играют люди. Ответы реально регистрируются в базе, а вы смотрите происходящее вживую на `/display`, `/admin` и `/host`. Это репетиция и проверка системы без людей.

## Как запустить

**Кнопкой:** админка → вкладка «Демо» → «Полная симуляция турнира» → задайте параметры → «Запустить симуляцию». Ниже виден живой журнал, остановить можно в любой момент.

**Из терминала:**

```bash
npm run simulate -- --password ВАШ_ПАРОЛЬ
npm run simulate -- --password ВАШ_ПАРОЛЬ --teams 100 --blocks 3 --per-block 15 --question-sec 20
```

Параметры: `--url` (по умолчанию `http://127.0.0.1:3000`), `--teams`, `--blocks`, `--per-block`, `--question-sec`, `--pause`, `--block-wait`, `--reveal-step`, `--seed`, `--no-chaos` (без сбоев).

> **Внимание:** симуляция создаёт отдельный турнир «Симуляция …» (он помечен как демо) и делает его **активным**. Настоящие капитаны при этом отключаются и войдут заново, поэтому запускайте её, пока на сервере нет настоящей игры. Ваш настоящий турнир не удаляется, к нему можно вернуться во вкладке «Турниры».

## Что делают боты

| Поведение | Как смоделировано |
|---|---|
| Разные команды | у каждой своя «сила» (вероятность знать ответ) и темп (кто-то отвечает сразу, кто-то под конец таймера) |
| Сложность | на сложных вопросах ошибаются чаще и думают дольше, на лёгких реже |
| Сеть | у каждого устройства своя задержка 5–155 мс |
| Потеря связи | примерно у 5% ответов бот отключается посреди вопроса, ждёт 1–5 с и подключается снова |
| Поздние ответы | примерно у 6% бот отправляет ответ уже после закрытия вопроса (должен быть отклонён) |
| Повторы | примерно у 5% бот отправляет тот же ответ ещё раз (не должен продублироваться) |
| Молчуны | примерно у 5% бот вообще не отвечает |
| Форматы | вопросы вариантами и текстом вперемежку, лёгкие/средние/сложные, блоки |

## Что делает «ведущий» (скрипт)

Создаёт турнир, запускает автопроведение, между блоками ждёт и нажимает «Начать следующий блок», затем объявляет тройку призёров и показывает таблицу.

## Контрольный подсчёт

Каждый бот запоминает, какие его ответы сервер **принял** и были ли они верными. В конце скрипт сам считает ожидаемые баллы и сверяет с тем, что посчитал сервер: баллы, число ответов, число верных у каждой команды и число вопросов в архиве. Итог в журнале: `✓ Контрольный подсчёт: … совпали` или `✗` с перечнем расхождений. Те же проверки идут в автотестах (`tests/simulation.test.js`).

## Чего симуляция не заменяет

Боты работают на том же ноутбуке (через localhost), поэтому симуляция проверяет логику и нагрузку на сервер, но **не Wi-Fi, не роутеры и не поведение настоящих телефонов**. Этапы 2–3 плана испытаний нужно проводить с людьми и железом. Для нагрузки на 1000 клиентов есть отдельный `npm run load` (см. `НАГРУЗКА.md`).
