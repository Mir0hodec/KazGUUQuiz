# Нагрузочное тестирование: 1000 клиентов

Запуск: `npm run load` (1000 клиентов, сервер поднимается сам) или `node scripts/load-test.mjs 300`. Длинная игра: `ROUNDS=15 npm run load`. Против настоящего сервера: `node scripts/load-test.mjs 1000 http://192.168.1.10:3000 ПАРОЛЬ` (создаст отдельный турнир «Нагрузка 1000»).

## Что именно измеряется, и чего НЕ показывает этот тест

Все 1000 клиентов и сервер работают **на одном ноутбуке** (через localhost). Тест показывает, как справляется **сам сервер**: приём ответов, рассылка, подсчёт, сохранение. Он **не измеряет Wi-Fi**: реальные задержки будут выше и зависят от роутеров и сигнала. Wi-Fi остаётся главным ограничением (см. ниже).

Каждый клиент здесь отдельная команда (самый тяжёлый вариант: 1000 команд × 1 капитан).

## Результаты (MacBook, 10 ядер, 16 ГБ; Node.js 26)

| Что проверяется | До исправлений | После исправлений |
|---|---|---|

| Доставка вопроса на 1000 устройств (p95) | 332 мс | 19 мс |
| Размер сообщения-состояния на каждую команду | 50 КБ | 0,7 КБ |
| Шквал из 1000 ответов одновременно | **принято 15 из 1000 за 30 с, сервер завис** | **принято 1000 из 1000 за 0,03 с**, подтверждение p95 18 мс |
| Каждый ответ сохранён ровно один раз, дублей нет | не проверялось | да |
| Автооценка и баллы (1000 ответов) | не проверялось | сумма баллов совпала с расчётом |
| 1000 одновременных нажатий BUZZ | не проверялось | победитель один, подтверждение p95 40–59 мс |

### Что было не так и как исправлено

После каждого ответа сервер рассылал **всем** телефонам полное состояние со списком всех команд и всех ответивших: при 1000 командах это 50 КБ × 1000 телефонов на каждый из 1000 ответов, около 50 ГБ на один вопрос. На 30 командах это не было заметно. Исправлено:

- телефонам больше не рассылается список команд (экран входа берёт его отдельным запросом `/api/teams`) и список ответивших (остался счётчик);
- счётчик «ответили» обновляется только на проекторе и в админке и не чаще 4 раз в секунду;
- состояние админки при большом числе команд обновляется реже (до 2 раз в секунду на 1000 команд);
- запись состояния на диск стала адаптивной (дорогая запись реже), а журнал ответов дописывается отдельно каждые 200 мс;
- при открытии таблицы телефонам уходят только первые 100 строк, при раскрытии мест последние 12 (проектору достаточно, админ получает всё).

## Что остаётся ограничением

1. **Wi-Fi.** Одна точка доступа надёжно обслуживает порядка 30–50 устройств (зависит от модели). Для 1000 телефонов нужно **десятки точек доступа**, лучше на 5 ГГц, и коммутатор. Четырёх роутеров хватит на примерно 100–200 устройств, а не на 1000. Это нужно проверять на месте, этот тест Wi-Fi не проверяет.
2. **Проектор.** Таблица показывает первые 30 команд. Для итогов при сотнях команд используйте «Только десятка» / «Только тройка» и CSV «Итоги». Раскрытие «с последнего места» для 1000 команд означает 1000 нажатий.
3. **Админка.** Состояние админки при 1000 командах весит около 434 КБ на обновление: нужен нормальный ноутбук и стабильная сеть для него (лучше кабель).
4. **Карточки с QR на 1000 команд** (вкладка «Карточки входа») тяжёлые для браузера: печатайте частями или используйте CSV с PIN.
5. Лимит команд в одном турнире: 1000.
6. Тест выполнен на одной конфигурации ноутбука, на вашем оборудовании цифры будут другими. Повторите `npm run load` на нём.
